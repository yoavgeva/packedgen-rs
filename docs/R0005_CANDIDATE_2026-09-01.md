## Production diagnostics

`cache-diagnostics` remains the cold, observer-only reclamation snapshot.
`cache-production-diagnostics` adds relaxed atomic accounting only when
explicitly enabled. It exposes:

- current and peak entries/weight, soft-limit debt, and peak overshoot basis
  points;
- exact current and observed-peak retired entries and caller-accounted bytes;
- foreground hard-limit count and, with timing enabled, total, approximate p99,
  and maximum duration;
- background drain count, duration, starting debt, worker wakeups/runs,
  failures, and pending state;
- victim batches, candidates examined and removed, maximum candidates per
  batch, and native collection timing;
- size, doorkeeper, and frequency rejection causes, doorkeeper admissions and
  rotations, frequency-gate activation/transitions, and rolling-estimator CAS
  retries; and
- arena allocation requests, boxed allocation/reuse, current block storage,
  active/reusable slots and bytes, lifetime growths, and block releases.

`cache-pressure-timing` includes production diagnostics and adds `Instant`
sampling plus a fixed 64-bucket foreground histogram. Default builds contain
none of this state or request-path work.

The diagnostic race test deliberately overlaps guarded removal and readmission.
It found and fixed a transient negative observer delta: diagnostic accounting
now wraps without panicking, excludes transient negative states from peaks,
and obtains exact live capacity in the cold snapshot.

## What this freeze does not prove

This candidate is ready for R-0005 measurement, not for production release.
R-0005 must run from the exact tag and still demonstrate:

- exact peak logical capacity within the configured async hard limit;
- bounded reclamation and maintenance debt during long churn and stalled-reader
  tests;
- large-object and version-churn p99 regressions below 5%;
- peak physical memory within 10% of the strongest bounded baseline;
- scaling from one worker through every available core without a major
  throughput collapse;
- bounded rebuild/overlay peak memory and clean cache-drop memory behavior; and
- long soaks, failure/restart injection, fuzzing, and Linux-pinned sanitizer
  reproduction.

The rolling experiment is exploratory evidence from its recorded source hash,
not evidence for this later tag. R-0005 must publish fresh result bundles and
identify the tag in every record.
